## 4. Canonical Data Flow Model (2026)

Data flow across Wnode subsystems strictly obeys uni-directional synchronization paths.

```mermaid
sequenceDiagram
    autonumber
    participant Node as Edge Node / Telemetry
    participant Backend as nodld Daemon (Port 8080)
    participant Bolt as engine.db (BoltDB)
    participant EngineJSON as engine.json (Snapshot)
    participant CRM as crm.json (Canonical Store)

    Node->>Backend: Telemetry / Heartbeat Frame
    Backend->>Backend: Sanitize Node Invariants & Coordinates
    Backend->>Bolt: Execute ACID Transaction (Bucket: nodes)
    Backend->>EngineJSON: Atomic Periodic Flush (State Snapshot)
    CRM->>Backend: Identity & WUID Authentication Lookup
    Backend-->>CRM: Read Identity Verification Receipts
```

### 4.1 Invariant Validation Rules
1. **Coordinates & Telemetry Preservation**: Client-provided latitude and longitude values (`Lat`, `Lon`) are extracted from edge telemetry frames. Loopback default fallbacks are applied only when coordinates are `0.0000, 0.0000`.
2. **Deterministic Identity Resolution**: `WUID` tags (`100001-0426-01-AA`) serve as the canonical primary key joining CRM records, BoltDB staking balances, and telemetry node ownership.

## 5. Production-Grade Write Path

To guarantee concurrent safety across async execution workers and multi-process web proxies, all writes to disk follow a production-grade atomic write sequence:

```mermaid
graph TD
    A["Write Event Triggered"] --> B{"Target Data Store"}
    B -->|CRM Record Update| C["Write to Temp File: /var/wnode-data/crm/crm.json.tmp"]
    C --> D["Verify JSON Schema Integrity"]
    D --> E["Atomic Rename: fs.renameSync(tmp, crm.json)"]
    
    B -->|BoltDB Transaction| F["Begin Transaction: db.Update(func(tx *bolt.Tx))"]
    F --> G["Mutate B+Tree Bucket"]
    G --> H["Commit Transaction & Sync mmap Disk Page"]
    
    B -->|Engine Snapshot| I["Serialize In-Memory Map"]
    I --> J["Write Temp: engine.json.tmp"]
    J --> K["Atomic File Swap: rename(tmp, engine.json)"]
```

> [!WARNING]
> Direct non-atomic buffer writes (`fs.writeFileSync` without temp swap) to live database files are prohibited. Atomic file swapping prevents partial-page writes during unexpected host process restarts.
