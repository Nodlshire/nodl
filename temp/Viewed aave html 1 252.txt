   <h2 class="text-2xl font-bold mt-12 mb-6 text-white border-b border-slate-800/50 pb-2">3. Protocol Overview</h2>
   <ul class="list-disc pl-6 space-y-2 my-4 text-slate-300">
   <li class=""><strong class="font-bold text-slate-200">Architecture</strong>: Aave V3 utilizes a decentralized pool architecture managed by a central <code class="text-sm font-mono text-slate-300">Pool</code> contract, governed by a <code class="text-sm font-mono text-slate-300">PoolConfigurator</code>. Assets are isolated into specific eMode categories to optimize capital efficiency.</li>
   <li class=""><strong class="font-bold text-slate-200">RPC Surfaces</strong>: Uses standard EVM JSON-RPC <code class="text-sm font-mono text-slate-300">eth_call</code> and <code class="text-sm font-mono text-slate-300">eth_sendRawTransaction</code> endpoints, strictly requiring block height parameters for all state reads.</li>
   <li class=""><strong class="font-bold text-slate-200">Data Models</strong>: Employs complex structs including <code class="text-sm font-mono text-slate-300">ReserveData</code>, <code class="text-sm font-mono text-slate-300">UserAccountData</code>, and <code class="text-sm font-mono text-slate-300">EModeCategory</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Proof Models (if applicable)</strong>: Relies on Ethereum state roots (Merkle Patricia Tries). The Sovereign Mesh independently verifies the state root via Light Client endpoints or decentralized RPC quorums before confirming the step hash.</li>
   </ul>
   <h2 class="text-2xl font-bold mt-12 mb-6 text-white border-b border-slate-800/50 pb-2">4. Deterministic Adapter Specification</h2>
   <ul class="list-disc pl-6 space-y-2 my-4 text-slate-300">
   <li class=""><strong class="font-bold text-slate-200">Deterministic RPC Wrapper</strong>: The adapter intercepts EVM <code class="text-sm font-mono text-slate-300">eth_call</code> requests. If the RPC provider exceeds 2000ms latency, drops the connection, or returns varying nonce errors, the adapter aborts immediately and maps the failure to <code class="text-sm font-mono text-slate-300">NETWORK_UNAVAILABLE</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Deterministic Error Mapping</strong>: Revert strings (e.g., <code class="text-sm font-mono text-slate-300">35</code> for &quot;Health factor lower than liquidation threshold&quot; or <code class="text-sm font-mono text-slate-300">42</code> for &quot;Reserve inactive&quot;) are mapped cleanly to Mesh deterministic error strings. Non-standard RPC HTTP errors are masked as <code class="text-sm font-mono text-slate-300">REMOTE_ERROR</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Deterministic Response Normalization</strong>: Hexadecimal EVM responses are decoded. BigInt values are converted to canonical base-10 strings. Addresses are forcefully lowercased. Any arrays are strictly sorted.</li>
   <li class=""><strong class="font-bold text-slate-200">Deterministic <code class="text-sm font-mono text-slate-300">payloadHash</code> Generation</strong>: The normalized JSON object is serialized without whitespace, and hashed via <code class="text-sm font-mono text-slate-300">SHA-256</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Deterministic <code class="text-sm font-mono text-slate-300">integrityProof</code> Generation</strong>: A secondary HMAC <code class="text-sm font-mono text-slate-300">SHA-256</code> hash is generated combining the <code class="text-sm font-mono text-slate-300">payloadHash</code> with a secure mesh salt.</li>
   <li class=""><strong class="font-bold text-slate-200"><code class="text-sm font-mono text-slate-300">determinismProfile()</code></strong>: Returns <code class="text-sm font-mono text-slate-300">{ isPurelyDeterministic: true, reliesOnTime: false, reliesOnRandomness: false }</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Capability Map</strong>: Returns <code class="text-sm font-mono text-slate-300">{ canFetch: true, canSubmit: true, canValidate: true }</code>.</li>
   </ul>

   <h2 class="text-2xl font-bold mt-12 mb-6 text-white border-b border-slate-800/50 pb-2">7. Proof of Compute Pipeline</h2>
   <ul class="list-disc pl-6 space-y-2 my-4 text-slate-300">
   <li class=""><strong class="font-bold text-slate-200">RPC Normalization</strong>: A workflow step requests <code class="text-sm font-mono text-slate-300">getUserAccountData</code> at a specific block height <code class="text-sm font-mono text-slate-300">N</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Calldata Hashing</strong>: The step payload <code class="text-sm font-mono text-slate-300">{&quot;asset&quot;: &quot;0x...&quot;, &quot;block&quot;: N}</code> is cryptographically hashed.</li>
   <li class=""><strong class="font-bold text-slate-200">WASM Execution Hashing</strong>: The returned values (<code class="text-sm font-mono text-slate-300">totalCollateralBase</code>, <code class="text-sm font-mono text-slate-300">totalDebtBase</code>, and <code class="text-sm font-mono text-slate-300">healthFactor</code>) are decoded, converted to canonical strings, and hashed into the <code class="text-sm font-mono text-slate-300">payloadHash</code>.</li>
   <li class=""><strong class="font-bold text-slate-200">Quorum Verification</strong>: Nodes 1, 2, and 3 simultaneously hit their respective RPCs at block <code class="text-sm font-mono text-slate-300">N</code>. If any RPC returns varying state (due to archive node syncing issues), the <code class="text-sm font-mono text-slate-300">payloadHash</code> diverges, and the network quarantines the out-of-sync node.</li>
   <li class=""><strong class="font-bold text-slate-200">Replay Determinism</strong>: Because the call is explicitly bound to block <code class="text-sm font-mono text-slate-300">N</code>, any future replay of this workflow will query archive nodes at block <code class="text-sm font-mono text-slate-300">N</code>, guaranteeing identical output hashes perpetually.</li>
   </ul>
